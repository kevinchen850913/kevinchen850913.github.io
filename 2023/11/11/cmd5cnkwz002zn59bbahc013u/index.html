BMC(1)-BMC 學習筆記

發表於2023-11-11|更新於2025-07-16

# BMC 是什麼

基板管理控制器（BMC）是一種小型專用處理器，主要用於遠端監控和管理伺服器或其他主機系統。BMC 通常基於 ARM 架構的系統單晶片（SoC），並內建圖形處理和邏輯控制功能。它一般安裝在電腦、伺服器、網路設備或儲存裝置的主機板上，並可透過專用或共用網路進行遠端存取。

BMC 具有多個連接介面，能夠通過感應器、快閃記憶體（如 BIOS/UEFI）來監控硬體狀況。它還可以透過序列接口或實體／虛擬 KVM（鍵盤、顯示器、滑鼠）來提供主控台存取權限，並記錄主機的事件和電力循環日誌。

# BMC 的主要功能

BMC（基板管理控制器）具備多項遠端管理和監控功能，以下是其主要功能：

  1. 遠程電源控制（開關電源 / 重啟 / 狀態監控）
    用戶可以遠端開啟、關閉或重啟伺服器，並且監控伺服器的電源狀態。
  2. 串口重定向（Serial over LAN, SOL）
    允許透過網路對伺服器的串口進行遠端重定向，使使用者可以像直接連接到伺服器的串口一樣進行操作。
  3. KVM / 虛擬化管理（KVM/VM）
    提供虛擬鍵盤、顯示器和滑鼠（KVM）功能，遠端控制伺服器，即便伺服器的操作系統無法啟動，仍可進行管理。
  4. 硬體資訊獲取及資源管理
    包括監控伺服器的溫度、風扇轉速和電壓等硬體狀況，幫助管理員及時發現潛在的硬體故障。
  5. 系統事件日誌（SEL，System Log）
    記錄伺服器的系統事件，包括硬體故障、警告訊息等，幫助管理員追蹤伺服器狀態和進行故障排查。
  6. 集群管理
    支援多台伺服器的集中管理，提升大規模伺服器環境中的管理效率。
  7. 調試與定位
    提供遠端的故障診斷和問題定位功能，協助系統管理員快速解決伺服器故障。

註： 儘管上述許多功能並不完全符合 IPMI（智慧平台管理接口）的標準協議，但為了使用方便，各廠商逐步開發並完善這些功能，並將其作為現今伺服器管理中不可或缺的工具，例如 KVM 功能。

由於 BMC 軟體的開發相對複雜且投入成本較高，因此許多廠商會選擇購買第三方的 BMC 軟體，再根據自己的需求進行開發。當前能夠提供完整 BMC 軟體的公司主要有兩家：愛迪生（Edison）和 AMI（American Megatrends）。

市場上獨立開發完整 BMC 功能的廠商並不多，這些廠商的大多數 BMC 軟體都是基於 Emulex、愛迪生或 AMI 的代碼進行開發和改進的。

# BMC 和 IPMI 的關係

BMC（基板管理控制器）與 IPMI（智慧平台管理接口）息息相關，兩者的關係如下：

BMC 是一種硬體模組，專門用於伺服器的帶外管理。最早，每個廠商的 BMC 模組都是私有的，這使得不同廠商的伺服器管理變得十分麻煩。假設一個機房中有多個不同廠商的伺服器，管理員就需要安裝每個廠商不同的管理軟體，且這些管理軟體的功能和操作方式也各不相同。為了解決這一問題，Intel 主導制定了 IPMI 協議標準，這使得不同廠商的 BMC 可以通過統一的接口進行管理，極大地提高了伺服器的兼容性。

然而，對於 BMC 而言，IPMI 協議只規範了一些基本功能，例如開關電源、獲取傳感器狀態等。許多進階功能，如 KVM 控制和功耗管理等，仍需要各家廠商根據自己的需求進行實現。因此，儘管 BMC 可以遵循 IPMI 協議進行基本管理，許多高級功能還是需要廠商自行開發。

# 伺服器管理：帶內管理與帶外管理

在伺服器領域，管理方式可分為「帶內管理」和「帶外管理」兩種：

  • 帶內管理：帶內管理是通過伺服器的主 CPU 進行監控，通常需要在主機上安裝管理軟體（稱為 Agent）。由於管理是由主 CPU 執行，因此可以取得所有伺服器的資訊，功能相對完整。
  • 帶外管理：帶外管理則不依賴主 CPU 進行監控，而是通過 BMC 處理。這意味著不需要在主 CPU 上安裝任何軟體，因此也稱為無代理（Agentless）管理。由於 BMC 無法直接訪問伺服器的所有資源，帶外管理的功能相對較弱，但它仍能提供基本的遠端監控和控制。

# BMC 如何實現帶外管理

從上述介紹可以看出，BMC 實現的正是帶外管理功能。這意味著 BMC 能夠在伺服器未啟動操作系統的情況下，仍然提供遠端管理功能。例如，當伺服器操作系統無法啟動時，BMC 仍然能夠進行硬體監控和故障診斷。

需要注意的是，BMC 並非伺服器中必須具備的元件。事實上，許多低成本的伺服器可能沒有配備 BMC 模組，或者僅具備 BMC 的部分功能。原因在於 BMC 模組和相關軟體開發的成本相對較高，而在某些應用場景中，這些功能可能並非必須。這樣的系統仍然可以正常運行，只是缺乏帶外管理功能。

# 不同廠商的命名方式

不同伺服器廠商會根據自身需要對 BMC 模組進行命名，以區別於其他廠商。例如，惠普（HP）將其 BMC 系統稱為 iLO（Integrated Lights-Out），戴爾（Dell）則稱為 DRAC（Dell Remote Access Controller），而某些其他廠商則可能使用不同的名稱，如 HMD。雖然這些名稱不同，但實際上它們都是基於相同的 BMC 技術，只是在功能和特色上有所區別。

# L1 - L11 伺服器製造流程

在伺服器的製造過程中，根據不同階段的需求，通常會分為 11 個等級，這些等級被用來描述伺服器從初步製造到最終完成的過程。以下是各等級的簡要介紹：

# 製造流程：L1 至 L6

L1 至 L6 代表伺服器製造過程的初期階段，這些階段是業界標準的術語，用來描述伺服器製造過程的不同層級。這些階段通常涵蓋了基本的硬體組裝、測試和初步設置，為後續的更高階製造階段奠定基礎。

# 製造流程：L6 至 L10

L6 至 L10 是由超大規模企業（如原始設備製造商，OEM）負責執行的製造階段。在這些階段，企業會：

  • 重塑系統、產品或組件的品牌。
  • 鎖定硬體系統、產品和組件。
  • 在硬體上預先載入並鎖定相關的軟體。
    這些步驟通常涉及對硬體和軟體的深入整合，確保產品符合特定需求。

# 製造流程：L10 至 L11

L10 至 L11 代表製造過程的最後階段。在這個階段，完整的硬體和軟體系統將形成一個可提供各種服務的設備，例如 IaaS（基礎設施即服務）、PaaS（平台即服務）、SaaS（軟體即服務）、AI（人工智慧）、HPC（高效能計算）、深度學習及機器學習等。這些設備包含了服務提供者啟動其服務所需的一切。

# 刀鋒伺服器 (Blade Server)

刀鋒伺服器是一種單板伺服器，最早於 2001 年由 RLX 公司提出。與傳統的直立式伺服器相比，刀鋒伺服器具有更加緊湊和高效的設計，主要用於節省空間並提高管理效率。

# 傳統伺服器與機架式伺服器

傳統的直立式伺服器通常體積較大，佔用的空間也較多。在企業使用多台伺服器時，這些伺服器的存放空間會變得非常可觀。為了解決這個問題，機架式伺服器應運而生，將數台伺服器集中安放在機櫃中進行統一管理，從而有效節省空間。

# 刀鋒伺服器的設計

刀鋒伺服器是機架式伺服器的一種進化型設計，靈感來自網路和電信裝置的卡板式設計。它比機架式伺服器更能有效地節省空間，且具有更高的商業運用價值。刀鋒伺服器有一個完整的機座，提供集中式的電源、風扇散熱和網路通訊等功能。基座上可以安裝多張單板電腦，因其形狀像刀片（Blade），因此得名 “刀鋒伺服器”。

# 電源和散熱需求

由於刀鋒伺服器的單板電腦密集安裝，對電源和散熱的需求比一般伺服器更高。在散熱不良的環境下，刀鋒伺服器比傳統伺服器更容易發生過熱並導致系統故障。因此，在設計和部署刀鋒伺服器時，需要特別注意其散熱問題。

# 刀鋒伺服器的應用

在機房中，許多伺服器托管服務依照租用的頻寬進行計費，而非根據機櫃空間計費。因此，對於頻寬計費的伺服器代管機房來說，刀鋒伺服器並不是最常見的選擇。然而，對於按機櫃空間單位數計費的機房，或者在叢集運算等高密度計算需求的環境中，刀鋒伺服器則是一個理想的選擇。它可以在有限的空間內容納更多的伺服器，從而提高資源的使用效率。
