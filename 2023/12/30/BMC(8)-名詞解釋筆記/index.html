BMC(8)-名詞解釋筆記

發表於2023-12-30|更新於2025-01-02

注意！本篇文章是我自己的解讀，可能會有不少錯誤之處。

# BMC 常見的術語

SDR：Sensor Data Record（傳感器數據記錄）。從字面上看，這是用來管理各種傳感器的模塊，例如溫度、電流和電壓傳感器等，都由 SDR 進行管理。它可以實現像設定閾值等基本控制。此外，像看門狗和風扇等模塊也屬於傳感器範疇，統一由 SDR 來管理。

SEL：System Event Log（系統事件日誌）。這是用來管理符合協議規定的日誌模塊，例如溫度超過閾值等事件。每條日誌都會對應一個代碼，這與我們通常理解的診斷日誌有所不同，並不完全是同一概念。

SMS：System Management Software（系統管理軟體）。專指運行在操作系統層面的軟體，比如 APP 團隊正在開發的 FIST 軟體。然而，根據規範，SMS 僅限於本地運行的軟體，遠程訪問的軟體則不在其範疇內。

SOL：Serial Over LAN（串口通訊協議）。這個技術將串口資訊通過網路方式傳輸，省去了需要接上串口線的麻煩，特別適用於一些特殊的應用場景。

EMCP/RMCP+：這是基於 UDP 協議開發的專門用於 Pre-OS 環境中的網路通訊協議。在 IPMI 協議中，所有網路數據的傳輸都依賴於此協議。

NCSI：Network Controller Sideband Interface（網路控制器側帶介面）。這是一套基於 RMII 協議的標準協議，用於 BMC 和 NIC 之間的通訊。

Shared Port：共享端口。這是基於 NCSI 協議發展出來的一種端口，可以同時與 BMC 和主 CPU 進行通信。

Dedicated Port：專用端口。這種端口僅能與 BMC 進行通信。

# Intel ASD

這個功能類似於用來除錯的筆記型電腦，具體包括以下幾個功能：

  1. 接收並處理來自遠端客戶端的偵錯請求訊息。
  2. 通過 JTAG 控制主機的 CPU。
  3. 將偵錯結果和回應訊息傳送回遠端客戶端。

OEM 命令：

  • 設定遠端偵錯服務 (Set Remote Debug Service)
  • 取得遠端偵錯服務資訊 (Get Remote Debug Service Information)

關於 ASD，是否支援以下功能呢？

  1. 可讀取主機的記憶體以及主機控制器寄存器的資料。
  2. 可以設定中斷點，當主機程式執行到中斷點時停下，讓遠端電腦可以查詢主機的記憶體及控制器寄存器資料。
  3. 允許主機進行單步執行。

# Intel ACD

自主故障轉儲 (Autonomous Crash Dump)

OEM 命令：

  • 設定 ACD 服務參數 (Set ACD Service Parameters)
  • 取得 ACD 服務參數 (Get ACD Service Parameters)

ACD 是一個較為複雜且具有吸引力的功能，它提供了 OOB（Out-Of-Band）除錯 CPU 的能力。如果是使用 Eaglestream 平台，還可以用來除錯 PCH 並收集崩潰日誌。

ACD 的主要功能是根據 crashdump_input.json 執行 PECI（Platform Environment Control Interface），並記錄結果，而真正的解碼過程仍然需要使用 Cscript 工具。

# RAID TP

RAID-TP (Triple-parity) 是 ES NAS 的一種特殊磁碟陣列模式。與 RAID-6 只有兩顆硬碟容量的檢查碼（Parity）不同，RAID-TP 具有三顆硬碟容量的檢查碼，因此最多可以容許三顆硬碟損壞，仍然能確保資料的正確性，比 RAID-6 更為安全。

  • IPMI - BRCM 庫選擇 (BRCM library select)
  • IPMI - 取得控制器數量 (Get controller count)
  • IPMI - 取得控制器資訊 (Get controller information)
  • IPMI - 十六進位轉換為 ASCII 字串 (Hex to ASCII Text String Converter)

# FW Update

雙記憶體更新設計允許將第二個記憶體的內容燒錄到第一個記憶體，並且支援雙開機檔案，這樣可以增強更新過程的安全性，防止燒錄失敗或資料遺失等問題。

  • 支援 HPM 手動回滾功能，客戶可透過此功能找回已存在的鏡像檔，該鏡像檔儲存在第二個 SPI 記憶體中。
  • 支援並行 BIOS 韌體更新，這項功能能讓除 BMC 以外的所有元件進行並行韌體更新。

OEM 命令：

  • 取得並行元件裝置清單 (Get Parallel Component Device List)
  • 開始並行韌體操作 (Initiate Parallel Firmware Operation)
  • 取得並行操作狀態 (Get Parallel Operation Status)

# MCTP over I2C

管理元件傳輸協定（MCTP）是由分散式管理任務群組（DMTF）設計的協議，用於支援構成平台管理子系統的不同智慧硬體元件之間的通信，進而提供監控和控制功能。該協議不依賴於底層實體匯流排的特性，並支持不同層級的訊息傳遞。MCTP 的通訊模型包括訊息格式、傳輸方式、訊息交換模式及操作端點特徵。

MCTP 的底層匯流排包括 SMBus/I2C、串列連接、PCI Express 和 USB。由於協議設計簡單且封裝開銷小，使得 MCTP 非常適合在各種平台上的系統韌體和集成式底板管理控制器（BMC）中實現和處理。

目前，支援 ARP 的 I2C 介面出現新的從屬位址與韌體固定位址衝突的情況。

解決方案：

  • 為這些裝置建立 PDK 掛鉤。
  • 在 PDK 掛鉤中維護一個資料結構，包含從屬位址、設備名稱及設備供應商 ID。
  • 在指派新位址給從設備之前，檢查該位址是否已存在於資料結構中，如果該位址已經存在，則不會改變從機位址，而是返回相同的位址。

# NIC TP

NIC 是最廣泛應用於 CEA-709 和 IP-852（乙太網路 / IP）通道的網路介面，基於核心技術提供高更新頻率與快速反應時間。所有 NIC 都相容於 NL220、ALEX、LonMaker 以及其他 LNX 3.x 和 LNS TE 應用程式。NIC 也與 NodeUtil32、NLUtil、OPC 伺服器及高效能的 ORION 應用程式相容。

NC-SI + MCTP
NC-SI（Network Controller Sideband Interface）被定義為一種協議與介面，專門用來管理控制器和一個或多個網路控制器之間的通信。

OEM 命令：

  • 取得以太網控制器資訊命令 (Get Ethernet Controller Information Command)
  • 參數類型 - MCTP 特定 (0x01) 及參數
  • 參數類型 - NC-SI over MCTP (0x02) 及參數

# NVME-MI

NVMe SSD 是一種使用 PCIe 接口的非揮發性快閃存儲設備，通常在伺服器或存儲系統中使用。NVMe SSD 有多種外形尺寸，例如 M.2 和 U.2，而在應用程式中，NVMe SSD 通常使用 U.2 或 U.3 規格。

NVMe 管理介面（NVME-MI）定義了一套完整的 NVMe SSD 管理標準，並支援帶外管理（OOB），使得使用者能夠對 NVMe 設備進行基本的管理、監控和升級等操作。以下是一些 NVME-MI 的主要特性：

  • NVMe-MI 是 NVMe SSD OOB 管理介面的標準。
  • 它運行在 MCTP（管理元件傳輸協定）協議之上。
  • 物理層使用 PCIe VDM 或 SMBus，預設從機位址為 0x1d，並且可以透過 SMBus ARP 變更。
  • NVMe-MI 支援使用 SMBus 協定來讀取設備狀態，獲取 SMART 警告、溫度、硬碟使用壽命百分比、供應商 ID 和序號等資訊。

然而，這種架構感覺上有些問題，因為各種介面如 NIC 和 NVME-MI 都試圖統一和併吞其他介面，這可能會引起一些異常情況。最終，這些問題往往需要透過 SMBus 的後門方案來解決。

架構流程：

  • NVME-MI → MCTP → PCIe
  • NVME-MI → SMBus

# Intel BHS MMBI

MMBI 庫支援

Intel Birch Stream-AP (BHS-AP)
Intel 的下一代 Sierra Forest 處理器將專為 Birch Stream-AP 平台設計，預計於 2023 年底推出。

記憶體映射 BMC 介面
Intel 推出了新一代高速 BMC 介面，但目前的驅動程式支援性仍有待改進。

AST2600 支援註冊
許多關於 AST2600 的問題目前無法給出確定的答覆或明確的解釋。例如，有人詢問新版本是否支援 2.6，但對於是否支援 2.5 則無法提供確定的答案。

常見問題：

  1. 客戶是否需要購買 MMBI TP，或是預設程式碼已經支援？
  2. 關於 Intel PFR 4.0 規範的支援問題，Archercity 是否已經支援？
  3. 未來是否計畫在 BHS 上支援 SP-X 的 PFR TP？

Intel PFR 版本支援：

  • Intel PFR 2.0 支援已開發於 SPX-12 AST2500 WilsonCity CRB。
  • Intel PFR 3.0 支援已開發於 SPX-13 AST2600 ArcherCity CRB。
  • Intel PFR 4.0 支援已開發於 SPX-13 AST2600 AvenueCity CRB。

# NVIDIA GPGPU TP

GPGPU SMBPBI 概述
通用圖形處理單元（GPGPU）是圖形處理單元（GPU）的一種，其主要區別在於 GPGPU 並非用於繪製動畫，而是幫助中央處理器（CPU）分擔計算任務。GPGPU 結合了不同的處理器，實現異質運算，並在許多創新科技應用中扮演重要角色，如機器學習和深度學習。

SMBPBI - SMBus 信箱介面
NVIDIA 提供了一套專有規範，定義了如何管理 GPGPU 等設備的命令集，並支援透過 I2C 或 PCIe 通訊來操作這些設備。

使用兩種解決方案：

  1. 有 HMC（硬體管理控制器）：
    • 在 FPGA 中使用 Fencing 概念來避免 BMC 和 HMC 與 FPGA 通訊之間的衝突（如 Viking、Oberon 平台）。
    • 主機 BMC 通過 USB 介面與 HMC 通訊，並聚合來自 HMC 和主機 BMC 的回應。
    • 主機 BMC 使用操作碼 A3h 存取 SMBPBI 伺服器，並預設情況下由 HMC 具有 SMBPBI Fencing 權限。
  2. 無 HMC：
    • 在某些平台中，BMC 扮演 HMC 的大部分角色，並不需要使用 Fencing 概念。

# Redfish – GPGPU

目前尚未支援透過 Redfish 進行 ASD（遠端偵錯）操作，但 Redfish 標準提供了一套 RESTful 介面來管理伺服器、儲存、網路和融合基礎設施，並且可以用來管理 GPGPU 相關的設備。

Redfish 中的 GPGPU 相關功能包括：

  • 設備監控：收集與 GPU、FPGA 和 Baseboard 相關的遙測資料，並將其聚合到主機 BMC。
  • 設備事件：包括活動處理和活動日誌記錄。
  • 設備控制：支持各種控制操作，如限制電源、重設 PCIe、清除 GPU 警報、設定熱警報等。
  • 致命錯誤處理。
  • 韌體更新：支援對主機 BMC 及連接到 HMC 的設備進行韌體更新。

GPGPU Redfish 通訊
GPGPU 的 Redfish 通訊可透過 I2C 或 PCIe 進行，無需 HMC 的情況下，通過 USB 介面進行通訊。

主要命令：

  • 取得 / 設定寫保護模式 (Get/Set Write-Protect Mode)
  • PCIe 重設狀態設定 / 解除 (PCIe Reset State Assert/Deassert)
  • 設定 / 重置裝置模式（ECC）
  • 設定 GPU 最大功率控制
  • 清除 GPU 中斷狀態
  • 設定熱警報 / 超過閾值
