# Bitbake 簡介

讀取元資料並執行任務的工具。
https://docs.yoctoproject.org/bitbake/2.6/index.html

Yocto Project 中的主要建立工具。它是一個用於執行 build 任務和管理軟體包 build 過程的命令行工具，bitbake 會根據相應的配方 recipe 文件執行 build 流程。現在 BitBake 由 Yocto 與 OpenEmbedded 負責維護。

  • Python 語言實作，功能類似於 make，特別針對於嵌入式 Linux 交叉編譯器環境所設計研發。
  • 從根本上來說，BitBake 是一個通用任務執行引擎，允許 shell 和 Python 任務在複雜的任務間依賴約束下高效並行運行。
  • BitBake 包含客戶端 / 伺服器抽象，可以從命令列使用，也可以作為 XML-RPC 上的服務使用，並且具有多種不同的使用者介面。

Bitbake 工作流程

  1. Bitbake 透過平行調度任務來建立配方
  2. 它在 BBFILES 中查找配方 “.bb”
  3. 每個配方定義建置任務
    • 每個建置任務可以依賴其他任務
    • 每個配方可以依賴其他配方
    • 可以建立多個配方

# BitBake 安装

首先要下載 BitBake，BitBake 可以從這些來源取得。

  • OpenEmbedded 維護的 BitBake
  • OpenEmbedded 專案程式碼取出 BitBake
  • Yocto 專案程式碼取出 BitBake
  • 官方打包好的 BitBake

# 設定環境變數

# PATH

加入 bitbake 本體的位置，這樣才能在任意位置使用 bitbake。

# BBPATH

加入此環境變數才能找到工作區，工作區的相對路徑必須能找到 bblayers.conf、bitbake.conf、base.bbclass，此時 bitbake 才能正常運作。

提供另外一個方法，bblayers.conf 中加入 BBPATH := "${TOPDIR}" ，執行專案時即可加入環境變數，設定為當前目錄。

openbmc 使用 TOPDIR 來定義路徑。

# bitbake.conf

我對上面的變數分別做一個簡單的介紹

  • TMPDIR : 用於存放建置產生的文件，類似於輸出目錄，其中 TOPDIR 由系統自動賦值為工程目錄路徑。
  • CACHE : 指定存放快取文件的地方，透過這些文件，bitbake 可以在重新建置時省去很多工作。
  • STAMP : 戳記檔案存放目錄。
  • T : 存放臨時文件，如 log 文件。
  • B : bitbake 在這個目錄下進行建置工作。

測試過後 bitbake.conf 其實沒有那麼嚴謹，把上述的內容移至 bblayers.conf，該專案也是能夠正常執行，但檔案本體還是需要存在，不然編譯時系統會回報錯誤。
