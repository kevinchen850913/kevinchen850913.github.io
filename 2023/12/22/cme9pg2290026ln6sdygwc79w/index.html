# Linux 找檔案技巧

# Makefile

當我們需要編譯多個文件工程時，直接使用 gcc 可能不太方便。這時我們會使用 shell 的 make 命令。為了告訴 make 如何編譯和鏈接程序，需要編寫一個名為 Makefile 的文件。Makefile 描述了工程中文件之間的關係，並提供了更新每個文件的命令。簡而言之，Makefile 就是工程文件的編譯規則，使得項目工程的編譯變得自動化，無需手動輸入一堆源文件和參數。

參考檔案位置 : openbmc\build\evb-ast2600_kevin\workspace\sources\linux-aspeed\arch\arm\boot\dts\aspeed\Makefile

Makefile 會告訴編譯器，最後到底需要打包哪些檔案，但不代表所有的檔案都會被使用到，所以最後的產出 mtd 中，其實包含著一堆不一定會被使用的檔案。

參考格式

  • target : 規則的目標
  • prerequisites : 依賴的文件
  • recipe : 要執行的命令

目標變量
VPATH : 相對路徑或絕對路徑
vpath : 指定一種搜索模式 (關鍵字)

# Kconfig

在 Linux kernel 的目錄結構下，一般都會存在 Kconfig 和 Makefile 兩個文件。各級目錄下的 Kconfig 構成了一個分佈式的內核配置數據庫，每個 Kconfig 文件描述了所屬目錄源文件相關的內核配置菜單。當進行內核配置時，通常會執行 make menuconfig 命令，此時會出現內核的配置界面，從 Kconfig 文件中讀取配置菜單。用戶完成配置後，配置信息會保存到頂層目錄下的 .config 文件中。在進行內核編譯時，主 Makefile 會調用這個 config 文件，以了解用戶對內核的配置情況。

# Devtool 找 recipe 技巧

  • 參考範例 Modifying evb-ast2600 kernel，目標是找出 kernel、uboot 的精確名稱，包含版本或贅詞。
  • 如果多個 recipe 提供相同的項目，則 PREFERRED_PROVIDER 變數會決定首選哪個 recipe
  • 如果找到 recipe 名稱，devtool find-recipe 可以找到 recipe 位置

# 方案一 search

如果你很清楚 recipe 包含的關鍵字，或是 recipe 沒有太多雷同的檔案，此時使用 devtool search 加上關鍵字查出完整的名稱，範例中 aspeed 關鍵字可以鎖定唯一的 linux-aspeed。

使用 devtool find-recipe 加上剛剛查到的完整的名稱 (linux-aspeed)，就可找出 recipe 的位置。

# 方案二 evb-ast2600

在這個狀況中，你知道 kernel、uboot 的 recipe 與硬體息息相關，因此可以從 machine 一路反查出來源。

openbmc/meta-evb/meta-evb-aspeed/meta-evb-ast2600/conf/machine/evb-ast2600.conf

在 conf 文件中找到相依的檔案 ast2600.inc，繼續反查 ast2600.inc 的來源。(檔案也可以找到 KERNEL_DEVICETREE 、UBOOT_DEVICETREE)

在 openbmc 資料夾搜尋 ast2600.inc，得到位置 openbmc\meta-aspeed\conf\machine\include\，在 inc 文件中找到相依的檔案 aspeed.inc ，繼續反查 conf/machine/include/aspeed.inc。

conf/machine/include/aspeed.inc 檔案中可以找到 PREFERRED_PROVIDER 、 PROVIDERs，因此可以確定 recipe 的精確名稱，此時接續方案一就可找出 recipe 的位置。

# 方案三 BSP Layer

在這個狀況中，你知道你要查的 recipe 與硬體息息相關，而且文件中有明確規範其位置。
1 Board Support Packages (BSP) — Developer’s Guide — The Yocto Project ® 4.3.999 documentation

PREFERRED_PROVIDER 、 PROVIDERs 有可能會放在下方兩個位置。

第二個標準位置 meta-aspeed\conf\machine\include\aspeed.inc ，就是方案二查到的 aspeed.inc，所以 aspeed.inc 可以找到 PREFERRED_PROVIDER 、 PROVIDERs，因此可以確定 recipe 的精確名稱，此時接續方案一就可找出 recipe 的位置。

# 方案四 build log

如果你什麼都不知道，那 log 訊息中會寫專案到底用了哪個 recipe。
建置完整的專案 devtool build-image obmc-phosphor-image
這裡有 log 檔案 openbmc\build\evb-ast2600\tmp\log\cooker\evb-ast2600 在 20240130095947.log 中搜尋 kernel 就可以看到專案用了哪個 recipe。
