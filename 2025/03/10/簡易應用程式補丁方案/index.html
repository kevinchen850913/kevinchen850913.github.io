簡易應用程式補丁方案

發表於2025-03-10|更新於2025-03-14

# 軟體需求

我臨時收到一個有關後門軟體的緊急任務，功能類似修改產品的身分證，但該軟體的權限控管目前還未有結論，會議中要我提供幾個解決方案，要能管理使用者權限，但不能影響原有流程與功能。要能搭配使用者客製化，但管理上不能太複雜，管理單位沒有軟體技能，使用者作業環境沒有網路，總之該軟體還充滿了未知數。

參與單位說明

  • 工程單位：狀況外，負責產生軟體
  • 管理單位：需求單位，無軟體技能
  • 應用單位：狀況外，負責使用軟體

常見的權限管理方法

  • 登入帳號密碼
  • 線上權限審核
  • 時間訪問限制
  • 地點訪問限制

關鍵詞：簡單維護、相信管理單位、暫行方案

# 軟體說明

我的靈感是大家都不要管，軟體不寫死功能，讓管理單位自己去頭痛，提供半成品讓決策者能自由組裝，等決策者想好方向再提需求，或是直接使用組合版的成品，用功能未定的軟體來對抗不明的需求，用魔法對付魔法。

產出的專案由四個檔案所構成 README.txt、Builder.bat、App、App.exe，而使用者則分為兩個對像，負責產生出 App.exe 的管理者與 App.exe 的使用者。負責產生出 App.exe 的管理者，可以在不需要有任何工程背景的狀況下，加上有效時間與密碼補丁，使應用程式能完全脫離工程單位維護，讓權限控管回到管理者手上。

軟體檔案說明

  • README.txt : 使用說明、時間設定、密碼設定
  • App : 應用程式的半成品組件
  • Builder.bat : 打包合併 App + README.txt = App.exe
  • App.exe : 應用程式本體，會自我分析出設定

# 軟體知識點

  • 將 README.txt 轉成 Base64 容易被破解
  • App 就是專案產生 App.exe 去除副檔名
  • 只要註解自我檢查機制就可以直接 Debug
  • Builder.bat 流程確保失敗時檔案會被刪除
  • 如果忘記密碼就直接重新提供軟體
  • App.exe 已打包免安裝即可使用
  • Builder.bat 方案有機會被判定為病毒
