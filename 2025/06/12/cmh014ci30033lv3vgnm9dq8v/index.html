Google Drive API 學習筆記

發表於2025-06-13|更新於2025-10-21

# Google Cloud 基本介紹

教學概覽分成兩部分：
第一部分：GCP 共通設定（OAuth 授權、建立專案）
第二部分：Google Drive 相關 API 實作（Drive API / Sheets API）

為什麼要使用 Google Cloud ，只用 Google Drive 不行嗎？

Google Drive 是給人用的，API 是給程式用的

  • Google Drive 是給你用滑鼠、點點點上傳、下載用的。
  • 但如果你要用程式（例如 C#）去自動化操作 Google Drive 像是上傳、下載、列出檔案，那你就需要「Google 提供的 API」。
  • 這些 API 服務都在 Google Cloud Platform（GCP）裡管理。

各種線上 LOG 作法評估

方案 適合程度 特點 備註
Google Sheets（透過 Sheets API 上傳紀錄） 推薦 容易管理、Google 帳戶即可使用 適合輕量記錄，表格型資料
Google Drive + JSON/CSV 檔案上傳 中等 把 log 存成檔案直接上傳 比較像「備份」而非即時查詢
Google Firebase / Firestore 高階 實時資料庫、可擴充、支援多設備同步 免費有配額，但學習曲線略高
自架 API + 儲存到資料庫（如 MySQL / MongoDB） 最靈活 可擴充、可做報表、查詢彈性高 需架設伺服器與資安保護

最推薦：使用 Google Sheets 當作簡易後台 log 系統
優點：

  1. 用 Google Sheets 當簡易資料庫
  2. 你可用手機、電腦即時查看紀錄
  3. 無需自架伺服器
  4. 免費配額也夠用（每日 5000+ 寫入）

# Google API 共通設定

步驟 1：建立 Google Cloud 專案並啟用 API

  1. 前往 Google Cloud Console
  2. 建立一個新專案
  3. 啟用以下 API：
    • Google Drive API
    • Google Sheets API
      步驟 2：建立 OAuth 憑證
  4. 左側選單點選「API 和服務」 > 「憑證」
  5. 建立「OAuth 2.0 用戶端 ID」
  6. 應用程式類型選擇「桌面應用程式」
  7. 下載 JSON 檔案（這是你的 client_secret.json）
    步驟 3：安裝 NuGet 套件（C#）

# Service Account

「使用者完全不用跳出 Google 授權畫面、也不需要登入 Google」
那你要的就不是使用者帳戶的授權，而是使用 服務帳戶（Service Account）！
如何使用 Service Account 操作 Google Drive？

步驟 1：建立服務帳戶

  1. 前往 Google Cloud Console
  2. 選擇你的專案
  3. 左側選「IAM 與管理」➜「服務帳戶」
  4. 點「建立服務帳戶」，給它一個名字，例如：my-csharp-bot
  5. 建立完後點進服務帳戶，產生金鑰，格式選 JSON
  6. 把這個 JSON 檔放到你的專案目錄（例如：service_account.json）

步驟 2：將該服務帳戶加入你的 Google Drive 資料夾共用

  1. 開啟 Google Drive 中的某個資料夾
  2. 點選「共用」
  3. 將服務帳戶的 email xxx@my-project.iam.gserviceaccount.com
  4. 權限設為「查看者」或「編輯者」

# Google Sheet API

Google Sheets API 本身不能直接做 SQL 查詢，Google Sheets API 是一個很基礎的 API，它能讓你讀取範圍內的資料（像是 “Sheet1!A1:C10”）寫入或更新資料，但 不會幫你查詢或篩選資料（例如 WHERE name = ‘小明’）

# Google Visualization API

免費、無須額外開啟 API，它是 Google Sheets 內建的功能（不是 Google Cloud API），你只要能「存取那個試算表」，就可以使用它，沒有配額限制（至少在合理用量下是沒問題的）

條件 說明
試算表權限 必須是「公開」或「已共用」的
如果是私有表格 就不能直接用 HTTP GET 查詢，要透過 Sheets API 授權存取
API 配額 沒有正式配額限制（不像 Google Cloud API），但請避免惡意大量存取

# Log 中紀錄的內容

安全與隱私注意事項

  • 不記錄 email、IP、MAC、電腦名稱
  • 建立匿名代碼 + 地區
  • 所有紀錄都用非識別性資料
  • 若需 GDPR 合規，可提供「不紀錄模式」（opt-out）

免費 IP 地理位置 API

取得電腦名稱
這個方法非常簡單，直接透過 Environment.MachineName 取得電腦名稱。這會給你當前電腦的名稱（通常是用戶在安裝時所命名的名稱）。

取得 MAC 地址
MAC 地址是網路介面的唯一識別符，通常與硬體綁定。
這裡使用的方式會取得系統上所有網卡的 MAC 地址。

透過 System.Net.NetworkInformation 來取得 MAC 地址，這段程式碼會列出系統中所有的網路介面，並取第一個有效的 MAC 地址。你也可以選擇進一步過濾網路介面（例如僅選擇「有線」網卡或「無線」網卡）來確保獲得正確的資訊。

匿名裝置識別碼，法規問題

蒐集環境資訊（匿名）

方法 難度 是否隱私敏感 可推論內容
Windows 個人化設定 ⭐ 安全 語言、地區、使用習慣
NLP、影像辨識 ⭐⭐⭐ 需注意 政治、宗教、性別
穿戴設備 / 醫療資料 ⭐⭐ 高風險 健康、生理狀況

有一些方法是比較簡單的，能從 Windows 系統撈到「偏個人化的設定」來作為弱識別特徵或偏好推測依據。

雖然它們不能直接知道使用者的「人種、信仰」這類超敏感資訊，但確實能幫你建立一種「使用者輪廓模型」，而且不需要太複雜的技術。

項目 用途 / 可能推論 C# 寫法
系統語言 / 地區 推測使用者所在地區或文化背景 CultureInfo.CurrentCulture
時間格式 / 鍵盤設定 推測國別 / 語言 InputLanguage.CurrentInputLanguage
時區 地理位置（例如 UTC+8 幾乎可推台灣 / 中國） TimeZoneInfo.Local
UI 語言 使用者習慣語系（如 zh-TW、en-US） CultureInfo.CurrentUICulture
使用者名稱 偶爾能看出名字拼音、文化背景 Environment.UserName
安裝字型清單 推測偏好語言或文化（有藏文、阿拉伯文等） InstalledFontCollection
桌布路徑 看桌布檔名或類型 Registry 存取 Control Panel\Desktop
主題色彩 / 模式 偏好暗色或亮色、可推 UX 習慣 Registry: AppsUseLightTheme
