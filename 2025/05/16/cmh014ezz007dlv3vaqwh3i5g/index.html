使用 ClickOnce + GitHub Pages 輕鬆部署桌面應用程式

發表於2025-05-17|更新於2025-10-21

ClickOnce 是微軟在 .NET Framework 中提供的一項部署技術，旨在簡化桌面應用程式的安裝與更新流程。透過 ClickOnce，開發者可以將應用程式以簡單的方式發布給使用者，並讓系統自動處理安裝、更新與解除安裝等作業。這大幅減少了使用者在維護應用程式時的操作負擔，實現了輕鬆、無縫的使用體驗。

# ClickOnce 的特點

  • ClickOnce 應用程式通常以受限權限執行，不需管理員權限即可安裝與啟動，提升了系統安全性。
  • 開發者可透過 Visual Studio 建立並發布 ClickOnce 應用程式，選擇部署路徑，由 ClickOnce 處理後續的部署邏輯。
  • ClickOnce 支援整合數位簽章流程，開發者可輕鬆進行版本更新，無需額外撰寫更新腳本。

使用者只需存取部署位置，ClickOnce 便會自動下載並安裝應用程式。安裝完成後，系統會建立快捷方式並負責後續的版本更新管理。每次啟動應用程式時，ClickOnce 都會自動檢查是否有新版本並執行更新。

# 部署與安裝方式

ClickOnce 提供兩種主要部署方式，開發者可依需求選擇最適合的方案：

# 透過 Web 安裝

  • 部署方式：開發者將應用程式發佈到 Web 伺服器，並提供一個 URL 連結，讓用戶可以點擊該 URL 下載和安裝應用程式。
  • 適用情境：這種方式適用於需要通過網路遠端安裝和更新的情況。用戶只需通過瀏覽器訪問該 URL，ClickOnce 就會自動處理下載、安裝和更新過程。
  • 優點：
    • 方便快捷：用戶只需要點擊連結即可安裝應用程式，無需手動操作。
    • 支持遠程安裝：可以輕鬆地在任何地方通過 Web 連結進行安裝，無需物理媒介或本地安裝。
    • 自動更新：用戶啟動應用程式時，ClickOnce 會自動檢查並下載新版本，實現自動更新。
  • 範例：企業內部應用程式可以通過公司內部網站提供 URL 讓員工進行安裝。用戶只需要在瀏覽器中點擊安裝鏈接，應用程式會被下載並安裝到本地。

# 透過文件共享

  • 部署方式：開發者將應用程式的安裝包發佈到本地網路中的共享文件夾（例如，網路磁碟機或共享文件夾），然後用戶通過文件路徑訪問該位置並執行安裝。
  • 適用情境：這種方式適合於內部網絡環境，尤其是當用戶位於同一區域網絡（LAN）時，開發者可以將安裝檔案放在內部的文件共享伺服器上，並讓用戶從該共享位置安裝應用程式。
  • 優點：
    • 內部網絡使用：如果應用程式僅在內部使用，且所有用戶都在同一個本地網絡，這是一個非常方便的選擇，無需依賴外部網路連接。
    • 直接控制：開發者可以控制共享位置，進行版本管理和權限設置。
  • 範例：例企業內部部署的一個應用程式，可以將安裝包放在公司內部伺服器上，用戶只需要在網路上找到相應的文件共享位置，點擊啟動安裝程式。

# 簽署數位簽章

在 ClickOnce 部署中，簽署應用程式是確保應用程式完整性與信任來源的關鍵步驟。透過數位簽章，可避免安裝包被竄改，提升使用者對應用程式的信任。

Visual Studio 支援使用數位憑證進行 ClickOnce 簽署。若希望自動化部署流程（例如整合至 CI/CD 工具如 Azure DevOps 或 GitHub Actions），可使用 SignTool 等命令列工具，在建置後自動完成簽署動作。

# GitHub Pages 托管

GitHub Pages 是 GitHub 提供的免費靜態網頁托管服務，通常用來部署 HTML/CSS/JS 網站，但也可作為 ClickOnce 安裝包的靜態資源伺服器。

使用方法：

  • 將 ClickOnce 部署包（如 .application 、 .manifest 、 .exe 等）上傳至 GitHub 的儲存庫中。
  • 啟用 GitHub Pages 並選擇存放部署包的分支或資料夾。
  • 使用 GitHub Pages 生成的 URL，將其作為安裝鏈接提供給用戶。

注意 Git 可能會自動轉換文字檔案的行尾格式（CRLF <-> LF），可能導致安裝檔案損壞，可執行以下指令關閉行尾轉換。

# 使用心得分享

我認為 ClickOnce 是傳統 C# 桌面應用程式最佳的自動更新解決方案，Visual Studio 提供完善支援，使安裝過程更少受到系統限制或安全提示干擾。

在個人專案中，我使用 GitHub Pages 來托管 ClickOnce 安裝包，不僅省去雲端儲存空間管理的麻煩，部署流程也快速且簡單。因此我打算將後續的小工具都改為支援自動更新的 ClickOnce 格式。

不過若應用程式用於商業環境，ClickOnce 有一些限制需要留意，例如：

  • 安裝路徑無法自訂，預設會藏在使用者目錄下的深層資料夾。
  • 無法整合高階安裝腳本或條件式安裝邏輯。
  • 安裝連結 URL 可被任意訪問，可能不符公司資安政策。

但如果僅用於公司內部網路環境，就能避開上述問題。近期我計畫將 ClickOnce 用於生產線工具的版本統一與集中部署，以解決工具散亂與版本不一致的問題。
