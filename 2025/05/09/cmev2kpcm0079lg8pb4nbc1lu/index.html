使用 Costura.Fody 打包單一可執行應用程式

發表於2025-05-10|更新於2025-08-28

我的目標是將應用程式的依賴項與核心功能打包成一個獨立單元，使應用更容易部署與管理。透過這種方式，可以避免在安裝過程中產生額外的系統設定或環境依賴，同時也能提供免安裝的可攜式版本，讓使用者可以直接執行，不需安裝、不留殘留資料。

這樣做不僅簡化了使用流程，對使用者而言也更有信任感與好感 —— 因為軟體不會在他們的系統中留下不必要的痕跡，也更容易在不同環境間移動與測試。

# Costura.Fody 方案

Costura.Fody 是一個 Fody 的附加套件，能將所有被引用的 DLL 都 嵌入為主執行檔（EXE 或 DLL）的一部分，於運行時動態載入，實現真正的單一檔案部署 ，用在 .NET Framework 或 .NET Standard 的 Windows 桌面應用非常適合，尤其想避免遺漏 DLL 或外部依賴的人，Costura.Fody 是常見選擇

使用 NuGet 安裝 Costura.Fody 套件，重新建置，即可產生出單一的應用程式，而 FodyWeavers.xml 中可以進行一些其他的設定，我自己體驗非常正面，安裝 Costura.Fody 後不用其他設定就能直接使用。

使用 Costura.Fody 要注意的事，不可以使用標記為「複製本機」的組件，要把它們作為資源嵌入到目標程式集中，才能順利的完成打包。

# ILMerge 方案

# ILMerge 是什麼？

ILMerge 是一個可以將多個 .NET 程式集合併為單一程序集的工具。雖然它不能將所有依賴項嵌入到一個 DLL 中，但可以將多個 DLL 文件合併成一個，簡化應用程式的部署。這樣做可以避免在部署過程中出現缺少 DLL 的情況。

使用 ILMerge
你可以下載並安裝 ILMerge，然後通過命令行工具將 DLL 文件合併。ILMerge 可以將 .NET 程式集（DLL）合併，但某些包含非託管程式碼的組件可能無法合併。建議使用 peverify 工具來檢查合併後的程序集。

# ILRepack 是什麼？

ILRepack 是 ILMerge 的開源替代工具，旨在解決 ILMerge 的一些性能和功能限制。ILRepack 可以作為一個 NuGet 包使用，並且提供更好的自訂選項。

# .NET 5/6+ 內建方案

對於 .NET 5/6 及更高版本，.NET 提供了自包含發佈（Self-contained deployment）功能，這可以將所有的依賴項和運行時一起打包成一個發佈包，讓應用程式可以在目標機器上直接運行，而不需要安裝額外的 .NET 執行時。

# PublishSingleFile

你可以在專案檔案中設定 PublishSingleFile 和 SelfContained 屬性來實現自包含發佈，這樣，所有的依賴項和 .NET 運行時會被打包到一個單一的可執行檔案中，簡化了部署過程。

使用 .NET Core 3.0 自带的 PublishSingleFile 属性合并依赖，其原理是生成一个启动器容器程序。最终没有对程序进行任何修改，只是单纯的打包而已。

# dotnet publish

你可以使用 dotnet publish 命令來生成自包含的發佈包，這樣會將應用程式及其所有依賴項打包成一個獨立的可執行檔案，便於部署。

# NuGet 方案

如果你的應用程式可以使用 NuGet，將 DLL 包裝成一個 NuGet 包，並將其添加到你的應用程式項目中。這樣，在安裝應用程式時，NuGet 會自動下載並管理所有的依賴項。

如果你的應用程式使用了第三方庫或內部的 DLL，將其包裝為 NuGet 包是一個常見的做法。NuGet 包可以自動管理依賴項並提供簡單的安裝方式。

  • 創建 NuGet 包：將 DLL 和相關文件打包成 NuGet 包，並將其發佈到 NuGet 伺服器或本地存儲庫。
  • 安裝 NuGet 包：在你的應用程式中添加 NuGet 包，NuGet 會自動下載並管理相關的依賴項。

這種方法非常適合管理多個依賴項和版本控制，特別是在大型項目中。

# 手動包裝依賴項

另一種方法是將所有的依賴項手動複製到你的應用程式的某個目錄中，並在應用程式中指定這些依賴項的位置。雖然這種方法比較直接，但缺乏自動化管理，且在面對多個版本的依賴項時容易出現問題。
