# 變數解析

BitBake 做的第一件事是解析基本組態元資料。基本配置元資料由專案 bblayers.conf 文件組成，以確定 BitBake 需要識別哪些層、所有必要的 layer.conf 文件和 bitbake.conf。

BitBake => bblayers.conf => layer.conf and bitbake.conf

  • BBPATH 用於分別搜尋 conf 、 classes
  • BBFILES 用於定位配 .bb 、 .bbappend

名為 “something_1.2.3.bb” 的配方會將

  • PN 設為 “something”
  • PV 設為 “1.2.3”

# BBFILES

BBFILES 可用檔案的空格分隔列表，並支援通配符，且追加檔案會依照它們在 BBFILES 中遇到的順序來套用。

配方文件集合的存在是為了允許使用者擁有.bb 包含相同套件的多個文件儲存庫。例如，人們可以輕鬆地使用它們來製作自己的上游儲存庫的本機副本，但進行了不需要上游的自訂修改。

# 預處理加速

如果一個物件可以重複使用，那麼問題就變成瞭如何用預先建構的工件替換給定的任務或一組任務。BitBake 透過「setscene」流程解決了這個問題。

當 BitBake 被要求建立給定目標時，在建立任何內容之前，它首先詢問快取的資訊是否可用於它正在建立的任何目標或任何中間目標。如果快取資訊可用，BitBake 將使用此資訊而不是執行主任務。

BitBake 首先使用 BB_HASHCHECK_FUNCTION 變數定義的函數 以及要建立的任務清單和對應的雜湊值來呼叫。此函數設計得很快，並傳回它認為可以獲得工件的任務清單。

# 開始執行任務

BB_NUMBER_THREADS 可以設定處理器數量。
任務可以是 shell 任務，也可以是 Python 任務。對於 shell 任務，BitBake 將 shell 腳本寫入 ${T}/run.do_taskname.pid ，然後執行該腳本。產生的 shell 腳本包含所有導出的變量，以及展開所有變數的 shell 函數。shell 腳本的輸出轉到檔案 ${T}/log.do_taskname.pid 。查看運行檔案中擴展的 shell 函數和日誌檔案中的輸出是一種有用的調試技術。

對於 Python 任務，BitBake 在內部執行任務並將資訊記錄到控制終端。BitBake 的未來版本會將函數寫入文件，類似於處理 shell 任務的方式。日誌記錄的處理方式也與 shell 任務類似。

BB_SCHEDULER 選擇用於調度 BitBake 任務的調度程序的名稱。

  • basic : 使用此選項會導致任務在解析時按數字順序排序。
  • speed : 首先執行有更多任務依賴它們的任務。speed 選項是預設選項。
  • completion : 使調度程序在構建開始後嘗試完成給定的配方。

BB_SCHEDULER 的研究結果
三種模式都不會實際影響任務的數量，所以實際編譯減少的時間十分有限，而且基於空間換取時間，所以優化的程度會受制於硬碟的速度。

# Shell or Python

Shell task 是由 shell 腳本執行的任務。這種任務通常用於執行一些基本的命令行操作，例如編譯原始碼、安裝檔案到目標系統、設定檔案權限等。Shell task 是直接在 shell 中執行的，因此可以使用標準的 shell 語法。
使用情境： 當需要執行一些不需要 Python 解釋器的基本命令時，可以使用 Shell task。它可以用於執行一些簡單的、不需要複雜邏輯的作業。

Python task 是由 Python 腳本執行的任務。這種任務通常用於執行複雜的、需要更多邏輯處理的操作，例如自定義編譯過程、檢查依賴關係、處理配置文件等。Python task 可以使用 Python 語法，具有更大的靈活性和功能。
使用情境： 當需要進行複雜的邏輯處理、依賴管理、配置文件處理等時，可以使用 Python task。Python task 通常用於處理更高層次的任務，並提供更多的自定義能力。

總結來說，Shell task 用於執行簡單的命令，而 Python task 用於執行複雜的邏輯和處理更高層次的任務。在 BitBake 中，這兩種任務可以根據實際需求進行組合，以構建完整的嵌入式 Linux 系統。

# 日誌記錄

bitbake 支援透過 BB_LOGCONFIG 變數對 Python 日誌記錄工具進行使用者定義的配置。此變數定義 JSON 或 YAML 日誌記錄配置 ，該配置將智慧地合併到預設配置中。

你可以建立一個 hashequiv.json 使用者日誌記錄設定文件。
