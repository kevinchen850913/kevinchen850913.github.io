OpenBMC(6)-Devtool_Cmd

發表於2024-06-08|更新於2025-07-28

devtool 是一個命令列工具，提供了許多功能來建置、測試和打包軟體，此指令與 bitbake 指令一起使用，devtool 指令是可擴充 SDK 的關鍵部分。

# devtool 基本介紹

# devtool 的功能

在過去開發者會直接修改專案中的檔案，然後重新編譯。

  • 使用 bitbake -c compile -fbitbake -C compile 或強制重新編譯，因為建置系統不知道你已經做了任何更改。
  • 很容易不小心丟失更改，例如運行 bitbake -c clean 會清除目錄。

devtool 可以執行建立補丁、檔案等步驟，bbappend 作為建立配方的一部分，Yocto 會建立一個 tmp/work/<architecture>/<recipe>/<version> 目錄，稱為「工作目錄」。這是建立配方的所有工作發生的地方，可以與 bitbake 的工作範圍做出區隔，命令 devtool 列的組織方式與 Git 類似，每個功能都有許多子命令。您可以運行 devtool --help 查看所有命令。

# devtool 工作區

devtool 使用 Workspace layer 層來完成建造。該層並不特定於任何單一 devtool 命令，而是整個工具使用的公共工作區域。

  • attic : 執行 $ devtool reset 時 devtool 保留內容
  • README : 提供有關工作區層中內容和管理方式的資訊。
  • .devtool_md5 : 檢查碼檔案。
  • appends : 包含 .bbappend 檔案的目錄，這些檔案指向外部原始碼。
  • conf : 包含 layer.conf 檔案的配置目錄。
  • recipes : 包含食譜的目錄。此目錄包含每個已添加的目錄的資料夾，其名稱與已添加的食譜相匹配。
  • sources : 包含構建食譜時使用的原始碼副本的目錄。這是在未提供原始碼路徑時使用的預設目錄。

# workspace attic

attic 的意思是閣樓，功能是資源回收桶，有些移除的檔案會被存入此位置。檔案要在 workspace 中才會被移除移入 attic，包含 srctree 與 .bbappend，而 .bb 則不會被移入，會直接被刪除。

Release notes for 4.1
https://docs.yoctoproject.org/dev/migration-guides/release-notes-4.1.html?highlight=attic

devtool reset now preserves workspace/sources source trees in workspace/attic/sources/ instead of leaving them in-place

devtool reset 現在將原始碼樹保留在 attic 中，而不是將它們留在原處。以此類推在 yocto project 4.1 之前的版本，reset 後 source tree 不會被移動 (刪除)，devtool reset 的行為會受版本影響。

# devtool finish

當修改完成後 (devtool finish)，會顯示 Leaving source tree ，此時檔案被移動到了 attic。

檢查 attic 資料夾中包含移除的 .bbappend 與程式碼。

# devtool reset

當修 devtool reset ，會顯示 Leaving source tree ，此時檔案被移動到了 attic。

檢查 attic 資料夾中包含移除的 meta-test-helloworld2.20240129164520 程式碼。

# attic 復原的可行性

devtool 沒有任何功能支援 attic 這個資料夾，甚至連刪除都必須使用者自己處理，但是 devtool 的 srctree 來源可以是 attic 中的檔案，實際測試也確實能這麼使用。

走左邊的指令，devtool add 後 workspace\sources 產生了 meta-test-helloworld2 的程式碼。

使用 devtool reset 移除 meta-test-helloworld2，移除的檔案被保留在 attic 中，所以 workspace\attic\sources 多出了 meta-test-helloworld2。

走右邊的指令，把垃圾桶作為來源，將垃圾連結出來，並沒有複製原始碼。

確認 meta-test-helloworld2 已重新進入工作區，此時就可繼續修改被 reset 的檔案。

# devtool 取得配方指令

相關的文件被放置在很奇怪的位置 (Autotools)，不過這三張圖一定要好好研究。
https://docs.yoctoproject.org/dev/sdk-manual/extensible.html#use-devtool-add-to-add-an-application

# devtool add <recipe>

新增配方，使用此指令將新配方新增至工作區層。
協助新增要建置的新軟體。

依照參數組合的不同，會產生三種流程

  • 只給來源位置，代表本地不存在原始碼，工作區會產生配置檔與程式碼本體。
  • 給來源位置與資料夾位置 (程式碼樹)，工作區會產生配置檔，程式碼放資料夾。
  • 只給資料夾位置，工作區會產生配置檔，程式碼會在原地修改。

本地操作測試

遠端有指定路徑測試

# devtool modify <recipe>

設定一個環境，使您能夠修改現有元件的來源。此指令與 add 指令非常相似， 不過使用 modify 時，本地層必須已經存在。

依照參數組合的不同，會產生三種流程

  • 只給來源位置，代表本地不存在原始碼，工作區會產生配置檔與程式碼本體。
  • 給來源位置與資料夾位置 (程式碼樹)，工作區會產生配置檔，程式碼放資料夾。
  • 只給資料夾位置，工作區會產生配置檔，程式碼會在原地修改。
  • 容量溢出錯誤 LOG

# devtool upgrade <recipe>

https://docs.yoctoproject.org/dev-manual/upgrading-recipes.html#using-devtool-upgrade
下拉配方，該命令將現有配方升級到上游配方的更新版本。該命令將升級後的配方檔案以及任何關聯檔案放入「工作區」中，並在必要時將來源樹提取到指定位置。在升級過程中，與配方相關的補丁將根據需要重新調整或添加。

更新現有配方，以便您可以為更新的來源檔案集建立它。

# devtool 取得資訊指令

# devtool search <recipe>

使用該命令搜尋可用的目標食譜。此指令會比對配方名稱、套件名稱、描述和已安裝的檔案。此指令顯示配方名稱作為符合結果。

# devtool status

工作區中的配方，使用該指令列出目前工作區中的食譜。資訊包括其各自的外部來源樹的路徑。

# devtool latest-version <recipe>

# devtool check-upgrade-status <recipe>

# devtool build <recipe>

建置配方，使用該命令來建立您的配方。
您可以使用 -s or --disable-parallel-make 在建置期間停用並行產生。

# devtool edit-recipe <recipe>

使用該命令在指定的配方上執行預設編輯器。

將 meta-test-helloworld 進行修改，devtool edit-recipe meta-test-helloworld 進入編輯畫面。修改的檔案為 workspace\recipes\meta-test-helloworld\meta-test-helloworld_git.bb，而專案中的 openbmc\meta-helloworld\recipes-meta-test-helloworld\meta-test-helloworld\meta-test-helloworld_git.bb 則未受到影響，保持為未修改的狀態。

執行 devtool finish meta-test-helloworld meta-helloworld -f ，將修改內容覆蓋至 openbmc\meta-helloworld\recipes-meta-test-helloworld\meta-test-helloworld\meta-test-helloworld_git.bb ，而 workspace\recipes\meta-test-helloworld\meta-test-helloworld_git.bb 則會被刪除，並不會被保留至 attic。

# devtool find-recipe <recipe>

這個指令跟 devtool search 使用方法接近，都是用來尋找 recipe，在成功找到 recipe 的情況下 devtool find-recipe 會顯示完整的檔案路徑，而 devtool search 只會顯示名稱。

devtool search 可以找出包含該關鍵字的檔案。

devtool find-recipe 所查找的名稱則必須完全相同。

# devtool update-recipe <recipe>

推送配方，如果要處理某些程式碼，可以使用 devtool modify 命令提取程式碼，當您對結果感到滿意並且已將變更提交至 Git 儲存庫時。

# devtool reset <recipe>

使用此指令從工作區圖層中刪除配方及其配置。如果該指令偵測到配方或附加檔案已被修改，則該指令會將修改後的檔案保留在工作區層下的單獨「attic」子目錄中。

# devtool finish <recipe>

注意下指令的位置，注意修改後沒有 commit，devtool finish 會失敗，如果沒招就只能 -f。

# devtool 對象測試指令

# devtool deploy-target <recipe> <target machine>

目標機器上部署，使用以下命令將配方的建置輸出部署到目標電腦。為了確保您擁有目標本地的所有依賴項，您需要確保在嘗試執行應用程式之前在目標上預先部署（安裝）了這些套件。
所以 deploy-target 是半調子的套件管理工具，不建議商用？

# devtool undeploy-target <recipe> <target machine>

使用該命令從目標電腦中刪除已部署的建置輸出。

# devtool build-image <image>

建置映像，使用此命令建立映像，將其擴展為包含工作區中配方中的套件。
