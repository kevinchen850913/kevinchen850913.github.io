# How to set BBPATH in OpenBMC

openbmc 使用 TOPDIR 來定義路徑，bblayers.conf 中加入 BBPATH := "${TOPDIR}" ，執行專案時即可將當前目錄加入環境變數。

TOPDIR
https://yocto.yoctoproject.narkive.com/FdE2rM5N/where-does-the-bitbake-get-the-variable-topdir
它在 “openbmc/poky/bitbake/lib/bb/parse/parse_py/ConfHandler.py” 中定義。當任何 bitbake 設定檔中未定義 TOPDIR 時，它會自動設定為目前工作目錄。

上述的資料是錯誤的，定義 TOPDIR 的位置不是在 ConfHandler，而是在 main、cookerdata，且機制也有些微的不同 。

lockBitbake 的呼叫堆疊
bitbake_main => setup_bitbake => lockBitbake

openbmc\poky\bitbake\lib\bb\cookerdata.py
findTopdir 的功能為判斷在 BBPATH 或 cwd 工作中的條目下搜尋 conf/bblayers.conf 如果失敗，bitbake 將退回到 cwd。
os.getcwd () : python 生態提供的取得當前工作目錄方法。

新舊版本差異
https://docs.yoctoproject.org/bitbake/2.6/bitbake-user-manual/bitbake-user-manual-execution.html#parsing-the-base-configuration-metadata
BitBake 首先在目前工作目錄中搜尋選用 conf/bblayers.conf 設定檔。如果 BitBake 找不到 bblayers.conf 文件，則假定使用者已直接在環境中設定 BBPATH 和 BBFILES 變數，所以 bblayers.conf 有機會可以省略，未實際測試，不過 openbmc 並不會如此使用。

# The difference between PN and PROVIDES

PN
2.2 Locating and Parsing Recipes
常見用法為使用 Recipes 檔案名稱來定義元資料片段。範例中 something_1.2.3.bb 的 PN 會設為 something，PV 設為 1.2.3。

如果不明確定義 PN，PN 會預設為檔案名稱。

openbmc\poky\bitbake\lib\bb\cache.py 檔案中解析 PN 的名稱替換機制，針對 RecipeInfo 的初始化中 self.pn = self.getvar (‘PN’, metadata) 如果失敗了，會改用替代方案 bb.parse.vars_from_file (filename,metadata) ，就是使用檔案名稱的第一段，此資訊會直接被記錄在 cache 所以後續就不會有沒有 PN 的問題。

Providers
PROVIDES 的功能是 PN 名稱之外別稱，透過 PROVIDES 變數明確建立的，該變數是可選的。

如果不明確定義 PN，PROVIDES 還是可以照常使用。

PN 與檔名不同
bitbake 可以接受此用法，但 OpenBMC 中不能這麼使用。

在 OpenBMC 專案中，檔案名稱與 PN 名稱不同會產生路徑錯誤，因為專案中 PN 會直接被拿來當路徑使用，名稱不同所以就會找不到檔案。這個用法在專案中出現超過千次，所以 PN 必須與檔案名稱相同。
