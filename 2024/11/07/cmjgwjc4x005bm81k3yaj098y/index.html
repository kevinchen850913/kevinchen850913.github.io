SREC 格式介紹與解碼程式範例

發表於2024-11-08|更新於2025-12-22

S-record 檔案格式是摩托羅拉公司在 1970 年代所創的檔案格式，此檔案格式也稱為 SRECORD、SREC、S19、S28、S37 或 MOT。

嵌入式系統的軟體開發工具可以將可執行檔及資料轉換為 S-record 格式。PROM 燒錄器可以讀取 S-record，燒錄到嵌入式系統的 PROM 或 EPROM 中。

個人推薦使用 Notepad++ 渲染 SREC 檔案。

# SREC 的限制

Unix 手冊中提到 :「每個 S-record 記錄的長度小於等於 78 個字元」
意旨雖然位元組數量可以填入 0xFF，但最好還是使用 32 個位元組以內，確保燒錄器可以支援 SREC 格式的燒錄。

# SREC 的註解

SREC 檔案格式不支援註解，但有些方法可以使用，要注意相容性。

  1. 有些軟體會省略開頭不是 S 的資料行
  2. 有些軟體會省略檢查碼之後的欄位
  3. 可以把註解放在檔案 (資料的結尾碼) 後面

# 紀錄種類

每行的開頭為 S，可以用來判斷是否符合格式。

  • S0 : 檔案標頭，位址長度 16-bit 通常為 “0000”，用來紀錄檔案的資訊而非資料。
  • S1 : 紀錄 16 位元的資料，位址長度 16-bit。
  • S2 : 紀錄 24 位元的資料，位址長度 24-bit。
  • S3 : 紀錄 32 位元的資料，位址長度 32-bit。
  • S4 ~ S6 : 可以跳過不使用（選擇性的記錄）。
  • S7 ~ S9 : 可以用來判斷資料的結尾。

# 位元組數量

由 16 進制的二位數組成，表示記錄中剩下的位元組數（16 進制二位數表示一個位元組），此欄位的最小值為 3，對應 16 進制的位址欄位加上一個位元組的檢查碼。

位元組數量計算範例
題目 : “S3” + “25” + “addr” + “data” + “crc”，求 data 長度。

  1. 0x25 轉十進位就是 37，計算單位是 bytes 或兩個 char
  2. 紀錄種類為 S3，所以 addr 的長度為 4 bytes
  3. 37 減去 addr 的長度 4 後變為 33 bytes
  4. 33 減去 crc 的長度 1 後變為 32 bytes
  5. 所以 data 長度就是 32 bytes

補充資訊

  • 如果是文字 (string) 要乘二，建議統一單位避免混淆。
  • 在此案例中 data 長度為上限的 32 bytes，所以在該欄位基本上不該看到大於 0x25 的數值。

# 位址

依記錄種類不同，位址可能是四位／六位／八位的 16 進制數字。

  • “S0” + “25” + “0000” + …
  • “S1” + “25” + “0000” + …
  • “S2” + “25” + “000000” + …
  • “S3” + “25” + “00000000” + …

# SREC 解碼程式

製作這個功能的目的為處理稍微過於老舊的 SREC 格式，將該資料轉換成連續的 bytes 資料，可以更有效率地進行燒錄，所以就使用能輕鬆處理文字的 csharp 來製作轉檔小工具。

簡單說明程式的邏輯，一開始先利用參數提供的 newLength 宣告 dataBytes，並填充 dataBytes 為全 0xFF 的容器，後續會將 SREC 解碼出的 address + data 貼到 dataBytes 即完成轉換，為了提高兼容性增加了 addressOffset 使 dataBytes 可以被平移更方便使用。
