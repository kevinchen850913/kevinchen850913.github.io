Git 垃圾過濾器 gitignore 教學

發表於2024-11-01|更新於2025-08-11

.gitignore 是 Git 版本控制系統中的配置文件，用於告訴 Git 哪些文件或目錄不應該被跟蹤和提交。這通常用來排除一些臨時文件、編譯產物或其他不需要的文件，以保持版本庫的整潔和高效，可理解為「忽略清單」。

已經列入版控的檔案，不受 .gitignore 檔案控制。

# gitignore 功能預覽

沒有使用 .gitignore 時會出現很多程式碼之外的檔案，可能是 Visual Studio 工具產生的那些暫存檔案或快取檔案。

有許多檔案並不需要列入版本控管，使用 .gitignore 後可以專注於程式碼的更動。

# 新建專案導入

您可以在儲存庫的根目錄中建立一個 .gitignore 文件，以告訴 Git 在提交時要忽略哪些文件和目錄。若要與複製儲存庫的其他使用者共用忽略規則，請將 .gitignore 檔案提交至您的儲存庫。

  • 在項目的根目錄下創建一個名為 .gitignore 的文件。
  • 使用文本編輯器打開 .gitignore ，並根據你的需求添加規則。
  • 保存並關閉 .gitignore 文件。
  • 確保 .gitignore 文件已經被 Git 跟蹤（通常 .gitignore 應該已經包含在版本控制中）。

有可能你已經在 GitHub 使用過這個功能，你可以選擇 GitHub 預先幫你定義好的忽略清單。

建立新 git 版本庫時我習慣會先提交兩個版本，第一個版本是全空白的提交，不包含任何檔案，僅提交文字訊息，而第二個提交就是 .gitignore 單獨提交該檔案，這兩個動作完成後才會開始放置檔案。

如果 .gitignore 失效，可以檢查是不是編碼方式不同導致，是不是 UTF-8、換行符號是否正確、有沒有不可見的符號，在 Linux 與 Windows 環境混用的時候要特別注意。

# 現有專案導入

如果專案已經運作一段時間，那想要導入 .gitignore 就不是那麼容易了，這取決於專案的維護中有無做好檔案的規劃，是否能利用簡單的資料夾或是附檔名排除無效的版本紀錄，若檔案控管不當，在導入 .gitignore 可能會使專案功能產生異常。

Git "不會" 忽略已經跟蹤的文件。

# 專案根除法

Git 可以一次性處理並忽略已經被 Git 跟蹤的文件。這需要用到 git rm --cached 命令，它可以將已經跟蹤的文件從版本控制中移除，但保留在本地工作區（即文件不會被刪除，只是不再被 Git 跟蹤）。

使用 git status 來查看有哪些文件被移除了，被移除的文件會顯示為 “deleted” 狀態，但這些文件仍然存在於本地。

完成移除後，提交這些更改。
最後，推送你的更改到遠程倉庫，這時問題才會開始出現。

如果這些文件之前已經提交到遠程倉庫，即使你將它們從本地 Git 跟蹤中移除，遠程倉庫中仍然會保留這些文件。如果不希望這些文件出現在遠程倉庫中，你可以選擇使用 git filter-branch 或 BFG Repo-Cleaner 等工具來徹底從歷史提交中刪除這些文件。

我再提供一個完全根除的方案，不是當前的本地資料潔淨，而是對整個 git 庫進行清洗，意思就是過往提交的檔案也會被忽略，但遠程倉庫的問題還是沒有辦法輕易處理，遠程倉庫的清洗不安全而且需要一點經驗。

  1. 提交目標 .gitignore 檔案
  2. 強制基變到 git 的初始節點
  3. 將 .gitignore 檔案向前移動至初始節點後
  4. 完成基變流程，你就得到一顆乾淨的版本樹

這個做法重新長了整顆的版本樹，會跟原本的庫完全不同，有點像是回到過去做出了改變，然後產生了一條全新的世界線，在我個人的 git 中我偶爾會做這種事，利用基變整理提交紀錄，整理好後再推送至主分支，而不是一開始提交就處理的這麼完美，都是錯覺。
