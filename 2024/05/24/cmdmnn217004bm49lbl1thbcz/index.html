# 變數拓展

變數拓展的基本用法，B 會被賦值為 preavalpost

運算子 = 不會立即展開右側的變數參考。擴展會被推遲，直到分配給的變數被實際使用為止。結果取決於引用變數的當前值。

:= 運算子會導致變數的內容立即展開，而不是在實際使用變數時展開

將此行為與立即變數擴展運算子 := 進行比較，如果對不存在的變數使用變數擴展語法，則字串將保持原樣。例如 BAR 只要 FOO 不存在，就會擴展為文字字串 ${FOO} 。

  • 與 Bourne shell 不同，單引號在所有其他方面的工作方式與雙引號相同。它們不抑制變數擴展。
  • 與 Bourne shell 不同，花括號是強制性的：Only ${FOO} 和 not  $FOO 被識別為 的擴展 FOO 。

個人心得變數拓展就像是 get 一樣，只有當拓展後的變數被使用時，才會執行 get 的動作，而 := 就是賦值時就去取得，所以髓位的及時與非即時，是由變數拓展值時的時間做為依據。

# 設定預設值

您可以使用 ?= 運算子來實現變數 更軟的 賦值。這種類型的賦值允許您在解析語句時定義未定義的變量，但如果變數有值則保留該值。如果 A 在解析該語句時設定了 ，則該變數將保留其值。但是，如果 A 未設置，則該變數將設置為 aval。

變數的弱預設值是在沒有透過任何其他賦值運算子為該變數賦值的情況下該變數將擴展為的值。 ??= 運算子立即生效，替換任何先前定義的弱預設值。

若有賦值行為 ( = ) 則會取代 ??= ，沒賦值 (append) 則會保留 ??= 。

# 覆寫語法

OVERRIDES 是 BitBake 中的專有名詞。 它的意思與一般口語中的意思不同。 OVERRIDES 是一個特殊的清單，用於記錄以冒號分隔的行為。 清單中的內容將在 BitBake 解析 recipes 和 configuration 後執行 。

OVERRIDES is a proper noun in BitBake. Its meaning is different from that in ordinary spoken language. OVERRIDES is a special list used to record colon-separated behaviors. The content in the manifest will be executed after BitBake parses the recipes and configuration.

這些指令不進行賦值，而是在已被賦值後進行修改。

這些運算子與 := 、 .= 、 =. 、 += 和 =+ 運算子的不同之處在於，它們的效果是在變數擴展時應用，而不是立即應用。

使用覆蓋語法時必須控制所有間距 (空格？)。

您可以使用刪除覆蓋樣式語法從清單中刪除值。指定要刪除的值會導致從變數中刪除所有出現的該值，不需要在值中添加前導或尾隨空格。當您使用此語法時，BitBake 需要一個或多個字串。周圍的空間和間距被保留。

手冊中有寫優先度排序 : :append => :prepend => :remove
這意味著不可能重新附加先前刪除的字串。

覆蓋式操作優點，若有一個 foo.bbclass 需要將值 val 新增至變數的類，請問 .bbclass 要怎寫才合適，還有會產生什麼結果。

如果 foo.bbclass 使用 :append 運算符。

# Python 語法

您可以使用內聯 Python 變數擴充功能來設定變數。

此範例導致 DATE 變數設定為目前日期。此功能最常見的用途可能是從 BitBake 的內部資料字典中提取變數的值 d。

透過使用「unset」關鍵字，可以從 BitBake 的內部資料字典中完全刪除變數或變數標誌。這兩個語句刪除了 DATE 和 do_fetch noexec 標誌。

指定用於 BitBake 的路徑名稱時，請勿使用波浪號～字元作為主目錄的捷徑。這樣做可能會導致 BitBake 無法辨識路徑，因為 BitBake 不會像 shell 那樣擴展此字元。所以請提供更完整的路徑。
