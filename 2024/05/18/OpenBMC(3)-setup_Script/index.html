# Shell 相關知識

# zsh

自 2019 年起，macOS 的預設 Shell 已從 Bash 改為 Zsh。
原始碼中出現 ZSH_NAME 是為了解決 Bash 與 Zsh 兼容性的問題。

# 判定字串的資料

  • test -z string
    判定字串是否為 0 ? 若 string 為空字串，則為 true
  • test -n string
    判定字串是否非為 0 ? 若 string 為空字串，則為 false，-n 可省略。
  • test str1 == str2
    判定 str1 是否等於 str2 ，若相等，則回傳 true
  • test str1 != str2
    判定 str1 是否不等於 str2 ，若相等，則回傳 false
    參考資料 : 鳥哥私房菜

# 利用判斷符號 [ ]

除了 test 之外，其實可以利用判斷符號 [ ] 來進行資料的判斷，舉例來說，如果我想要知道 ${HOME} 這個變數是否為空的，可以這樣做。

使用中括號必須要特別注意，因為中括號用在很多地方，包括萬用字元與正規表示法等等，所以如果要在 bash 的語法當中使用中括號作為 shell 的判斷式時，必須要注意中括號的兩端需要有空白字元來分隔。

# /dev/null 2>&1

/dev/null : 偽特殊文件，接受並丟棄所有輸入，不產生任何輸出。
2>&1 : 每當你執行一個程式時，作業系統總是打開三個文件，標準輸入、標準輸出和標準錯誤，這些文件的文件描述符分別為 0、1 、 2。所以 2>&1 簡單地說將標準錯誤重定向到標準輸出。
參考資料 : stackoverflow

# setup

# check the shell

The script must be sourced, not executed
必須是取得腳本，而不是執行腳本。

  • 取得腳本對環境的變更也會在目前 shell 中生效。
  • 執行腳本對環境的變更僅在子 shell 中生效，並在執行腳本時遺失。

所以這段的意思就是如果環境是 zsh 且執行腳本 setup，則 echo 後結束腳本，藉此方法可以避免腳本被執行，使 shell 本體環境的變更失敗。

# check the column

Linux 中的 column 指令用於按列顯示檔案的內容。
輸入可以取自標準輸入或文件，將命令分成多個列、行與進行填充。
