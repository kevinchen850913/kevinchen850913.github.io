AspeedPFR(1)-Introduction

發表於2024-07-13|更新於2025-07-28

# PFR 介紹

在 2017 年有個病毒 BrickerBot，他是透過網路刷機將 IoT 設備上的韌體變成磚頭 (Brick)，這種攻擊手法被稱為 PDoS (Permanent denial-of-service attacks /phlashing)，和 DDoS 讓服務器暫時癱瘓的攻擊手法相比，這是永久性的讓硬件癱瘓，必須重新更新才能復原。

隔年 (2018) 美國國家標準暨技術研究院 (NIST) 發布了 NIST SP 800 193 標準 (Platform Firmware Resiliency Guidelines)，裡面提及 Platform 上的 Firmware 應該要符合三項安全措施。

  • 保護 Protection，擋來路不明的命令。
  • 偵測 Detection，檢查檔案是否被更改。
  • 恢復 Recovery，回燒上一次的檔案。

# Intel PFR

英特爾平台韌體彈性 (Intel® Platform Firmware Resilience)，使用 FPGA 實作。

  • DETECT : PFR FPGA 會驗證 SPI flash 中的數位簽章，再比對每個 Region 的 Hash value，確認 Image 是否被竄改
  • RECOVERY : PFR FPGA 可 以自動恢復損壞的韌體，如果這個 BMC/BIOS 開不了機或一直重啟，這樣 PFR FPGA 就會自動將 Recovery 區塊放的 Image 燒到 Active 區塊)
  • PROTECT : PFR FPGA 監控與過濾系統匯流排上的惡意流量，原本很多 I2C Device 是直接對接 BMC 的，但現在會先經過 PFR FPGA，只有白名單上的指令才可以給 BMC

PFR 使用了一塊 CPLD 作為整個 PFR 技術的核心，並定義了一段特殊的預啟動狀態 T-1（T minus 1）。

系統上電後，先進入 T-1 階段，此時，其他所有具有可能啟動介面的韌體（PCH、CPU、ME、BMC 等）都處於重設狀態，只有 PFR CPLD 上電啟動，PFR CPLD 先對 BMC FLASH、BIOS FLASH 進行校驗。 如果校驗失敗，則 PFR CPLD 會擦除校驗失敗的 FLASH 區域，使用鏡像檔恢復 FLASH 數據，校驗成功則進入 Bootguard 的正常啟動模式，此後為 T0 模式。

在 T0 模式中，PFR CPLD 會對 SM BUS 和 SPI 資料進行監控過濾，開發者可以設定白名單，不符合白名單規則的資料會被阻止傳輸或寫入 FLASH，已達到過濾惡意資料的目的。

在 PFR 的安全架構中，BIOS FLASH、BMC FLASH 被分為了 3 部分，分為 active、recovery、staging。 active 中儲存的是未經壓縮的、直接執行的韌體，recovery 中儲存的是壓縮過得備份文件，staging 是用於升級的臨時緩衝區。

設備啟動時 pfr cpld 會對 active 進行校驗，校驗會通過後設備從 active 啟動。 校驗失敗時，pfr cpld 會將 recovery 中的鏡像還原到 active 中，然後重新啟動。

當系統韌體升級時，pfr cpld 會對升級包進行校驗，校驗成功後，首先將韌體放到 staging 中，然後系統重啟，重啟後 cpld 會將新的韌體寫入 active 和 recovery 區域。

# PIT

PIT 等級 1：平台鎖定 – 使用 RFNVRAM 中的密碼保護未經授權的開機

  • Intel PFR CPLD 和 RF NVRAM 設定隨機密碼（PIT 密碼）。
  • Intel PFR CPLD 在每次交流電源開啟時驗證 PIT 密碼，如果密碼不符則阻止開機。
  • 在出貨前，使用 RFID 槍從 RF NVRAM 中刪除密碼，並由最終用戶稍後啟用。

PIT 等級 2：平台韌體密封 – 使用雜湊資料保護未經授權的開機

  • 在出貨前，Intel PFR CPLD 運算平台 FW 的雜湊值，將其儲存在 CPLD UFM 中，並鎖定 UFM。
  • Intel PFR CPLD 即時重新計算平台韌體的雜湊值以進行驗證，如果不匹配則阻止開機

# ASPEED PFR

ASPEED PFR 是基於 AST1060 SOC 開發的整合硬體和韌體解決方案。 它受到英特爾 PFR 2.0 HRoT 解決方案 / 規範的啟發，並依賴開源社群提供的開源產品。

作為該專案一部分使用的開源產品是 Azure Cerberus 和 Zephyr RTOS。 Azure Cerberus 是一個開源程式庫，提供 HRoT 實現，該實現提供強制安全韌體啟動的功能。 Cerberus 專案的規範可以作為 Olympus 專案的一部分找到。

Zephyr RTOS 是一款與晶片無關的開源即時作業系統，它提供了一個小型、可擴展的即時作業系統 (RTOS)，針對資源受限的裝置進行了最佳化，跨多種架構。

ASPEED PFR 解決方案提供以下符合 Intel PFR 2.0 的 HRoT 功能。

# T-1 phase

ASPEED PFR 軟體在平台首次開啟（交流電源開啟）時在平台上建立一個特殊的預啟動環境，該模式稱為 T-1，旨在允許軟體運作與任何外部平台介面隔離，CPU、PCH、BMC、網路等均處於斷電或重設狀態。 T-1 條目僅在首次向平台施加交流電源期間（AC-on）或當平台偵測到需要更新的事件時進入。

在 T-1 模式下，AST1060 擁有所有平台快閃儲存的完全所有權，以執行身分驗證、復原和更新作業。 在偵測到 BMC 或 CPU 損壞或任何可能需要更新操作的問題時，AST1060 還可以將平台從常規模式轉換為 T-1。

  1. 韌體認證 Firmware Authentication
  2. 韌體恢復 Firmware Recovery
  3. 安全韌體更新 Secure Firmware Update
  4. 可現場更新的 HROT 韌體 Field Updatable HROT Firmware
  5. 韌體恢復 HROT Firmware Recovery HROT
  6. 安全啟動 HROT Secure Boot HROT

# T0 Phase

驗證通過後，韌體會釋放 BMC 和 CPU/PCH 重設訊號，讓 BMC 和 CPU 啟動，韌體進入 T0 階段。 從 T-1 到正常 T0 模式的轉換重點是為各個活動部分 PFM 定義的所有韌體儲存區域設定所需的保護。 此外，恢復部分為唯讀，而暫存部分則為可讀和可寫。

  1. 檢查點定時器 Checkpoint Timer
  2. SPI 過濾 SPI Filtering
  3. I2C/SMBus 過濾 I2C/SMBus Filtering
  4. SMBus 信箱 SMBus Mailbox
  5. 無縫更新 Seamless Update
  6. 運輸途中保護 Protect in Transit
  7. MCTP
  8. SPDM 認證 SPDM Attestation

aspeed-zephyr-project 該儲存庫提供了 AST1030 和 AST1060 的韌體應用程序，這些應用程式是在 Zephyr BSP 之上開發的，而搭配的 IC 就是 AST1060，用來取代 Intel 的 FPGA。

硬體偵測與保護引擎支援 4 組 QSPI 記憶體介面和 4 組 SMB 匯流排接口，以同時監控和保護 QSPI 事務（支援白名單中的 32 個 QSPI 指令。特定 QSPI flash 指令和透過暫存器過濾位址範圍）和 SMB 暫存器匯流排過濾（支援區塊表中的 128 個設備位址）。此 SOC 整合了 I2C、I3C、2 組 QSPI 主控制器和 GPIO，用於板通訊和韌體攻擊偵測。

保護 : BIOS 和 BMC 韌體的單 SPI 設備或雙 SPI 設備支持，運行時期間的 SPI 和 I2C/SMBus 過濾。檢查與救援：嵌入式 1MB 片上內部快閃記憶體（支援備用啟動復原（ABR）功能）

# intel-pfr PIT

  • PIT 功能僅在 intel-pfr 解決方案中支援。
  • PIT level 1 功能需要 Intel RFID 晶片，ASPEED PFR SDK 僅提供範例程式碼來模擬。
